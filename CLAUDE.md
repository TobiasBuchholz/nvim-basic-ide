# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What This Is

A personal Neovim configuration written in Lua. The target environments are TypeScript/JS, Python, C#/.NET (MAUI), and Ruby/Rails development, with AI tooling (Claude Code, Copilot, Amp).

## Development Workflow

There is no build step. Changes take effect by restarting Neovim or sourcing the changed file (`:source %`).

**Check health after changes:**
```
:checkhealth
:checkhealth <plugin-name>
```

**Reload plugins after editing `plugins.lua`:**
The file is configured to auto-run `:PackerSync` on save. Alternatively, run `:PackerSync` manually.

**Lua formatting** (used in CI/pre-commit):
```bash
stylua lua/
```
Config is in `.stylua.toml` (indent_width=2, column_width=120).

## Architecture

### Entry Point

`init.lua` is a flat list of `require("user.<module>")` calls. Load order matters: `impatient` must be first (startup caching), `plugins` before anything plugin-dependent.

### Module Layout

All configuration lives in `lua/user/`. Each plugin or feature gets its own file. The naming convention is the plugin's colloquial name (e.g., `cmp.lua` for nvim-cmp, `none-ls.lua` for null-ls).

**LSP is the exception** — it has its own subdirectory `lua/user/lsp/` with:
- `init.lua` — requires mason, handlers, none-ls in order
- `mason.lua` — server installer list
- `handlers.lua` — shared capabilities, diagnostic config, LSP keymaps
- `none-ls.lua` — formatters and linters
- `settings/` — per-server config files (omnisharp, pyright, sumneko_lua)

### Plugin Manager

Packer.nvim (`wbthomason/packer.nvim`). Plugins are defined in `lua/user/plugins.lua` as a single `use` table. Most plugins are pinned to specific commits. The compiled manifest lives in `plugin/packer_compiled.lua` — do not edit this file manually.

**To add a plugin:** Add a `use` block to `plugins.lua`, then run `:PackerSync`. Create a new `lua/user/<name>.lua` config file and `require` it in `init.lua`.

### Key Conventions

- **Leader key**: Space
- All keymaps go through `vim.keymap.set` (not the older `nvim_set_keymap`), typically defined in the module that owns the feature — except global navigation/editing keymaps which live in `keymaps.lua`
- Autocommands use `vim.api.nvim_create_augroup` / `nvim_create_autocmd` pattern
- Filetype-specific overrides go in `ftplugin/<ext>.lua` (currently only `cs.lua` for C# 4-space indent)

### Language-Specific Modules

**`maui.lua`** — .NET MAUI build commands. Defines custom Vim commands (`MauiBuildiOS`, `MauiBuildAndroid`, etc.) and user commands with completions for device names and configurations. Uses `vim.fn.system()` calls to `dotnet`. Firebase NuGet packaging commands are also here.

**`ror.lua`** — Ruby on Rails helpers via ror.nvim. Adds test coverage column highlighting (green=added, red=deleted lines), test runner integration, and navigation shortcuts for MVC files.

**`copilot.lua`** — GitHub Copilot configured with an `.asdf` Node shim path. Suggestion/panel display is disabled in favor of cmp source integration (via `copilot-cmp`).

**`claude-code.lua`** — claudecode.nvim with a snacks.nvim floating window (0.9×0.9, double border), horizontal diff layout.

### Completion Stack (cmp.lua)

Sources in priority order: LSP → Copilot → Lua → LuaSnip snippets → buffer → path. Snippets are in `snippets/` (JSON format, loaded by LuaSnip + friendly-snippets). Rails snippets extend the ruby filetype.

### Debugging (dap.lua)

DAP configured for Python (`debugpy`) and C#/.NET (`netcoredbg`). dap-ui opens/closes automatically on session start/end.

### Colorscheme

`colorschemes/darkplus.nvim/` is a git submodule — a VS Code-inspired dark theme. Loaded in `colorscheme.lua`.
